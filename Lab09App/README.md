Какие методы включает интерфейс IValueConverter и когда вызывается каждый из них?
Ответ: Два метода: Convert и ConvertBack. Convert вызывается при передаче значения из источника (модели) в цель (UI) — например, при отображении 
IsDone в цвет. ConvertBack вызывается в обратном направлении — из UI в источник, при двусторонней привязке (TwoWay). Если обратное преобразование 
не нужно, ConvertBack обычно бросает NotSupportedException.

– Как подключить конвертер к привязке?
Ответ: Сначала объявить конвертер в ресурсах (<local:MyConverter x:Key="MyConv"/>), затем указать его в привязке через свойство Converter: 
{Binding Property, Converter={StaticResource MyConv}}. При необходимости можно передать параметр через ConverterParameter.

– Какие элементы интерфейса умеют выполнять команды?
Ответ: Все, у которых есть свойство Command (от ButtonBase): Button, RadioButton, CheckBox, MenuItem, RepeatButton, ToggleButton. Также команды 
поддерживают Hyperlink, KeyBinding, InputBinding и ContextMenu-элементы. По сути, любой элемент, реализующий ICommandSource.

– Какую роль играет метод CanExecute и событие CanExecuteChanged?
Ответ: CanExecute возвращает bool — можно ли сейчас выполнить команду. По этому значению WPF выставляет IsEnabled у привязанных элементов 
(кнопка становится серой). CanExecuteChanged — событие, которым команда сообщает: «состояние изменилось, перепроверьте CanExecute». Без него 
кнопка не будет обновлять доступность.

– Почему RelayCommand нельзя реализовать без делегатов?
Ответ: Потому что RelayCommand — это универсальная команда «на все случаи»: она не знает заранее, что именно выполнять. Конкретное действие и 
условие передаются извне как делегаты Action<object> и Func<object, bool>. Без делегатов пришлось бы для каждой команды писать отдельный класс — 
тогда RelayCommand потерял бы смысл.

– Чем команда удобнее обработчика события нажатия кнопки?
Ответ: Команда отделяет логику от интерфейса: одна и та же команда может вызываться кнопкой, горячей клавишей, пунктом меню. Логика «можно/нельзя» 
лежит в CanExecute, а не размазана по обработчикам TextChanged/SelectionChanged. Кнопка сама включает и выключает себя. Это соответствует MVVM и 
упрощает тестирование — команду можно проверить без UI.
