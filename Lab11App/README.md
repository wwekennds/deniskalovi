Ответы на вопросы:
– Что такое сериализация и десериализация?
Ответ: Сериализация — это процесс преобразования объекта в последовательность байтов или в текстовый формат (например, JSON) для сохранения на диск или передачи по сети, а десериализация — обратный процесс восстановления объекта из этого формата.

– Какие методы класса JsonSerializer применяются и что они принимают и возвращают?
Ответ: Из класса JsonSerializer чаще всего применяются два метода: Serialize и Deserialize. Первый принимает сериализуемый объект (и при необходимости параметры JsonSerializerOptions) и возвращает либо строку, либо пишет данные в поток; 
в работе обычно используется перегрузка, возвращающая string, которую затем сохраняют в файл. Второй метод Deserialize<T> принимает строку или поток с JSON и возвращает объект указанного типа T, например List<TaskItem>; если JSON пустой или 
некорректный, метод может вернуть null, поэтому результат нужно проверять.

– Какие свойства и методы диалогов выбора файла использованы в работе?
Ответ: Для диалогов выбора файла в работе используются классы OpenFileDialog и SaveFileDialog из пространства имён Microsoft.Win32. У OpenFileDialog применяются свойства Filter (например, «JSON files (.json)|.json»), Title и метод 
ShowDialog(), возвращающий bool? — true, если пользователь выбрал файл; после этого путь берётся из свойства FileName. У SaveFileDialog аналогично используются Filter, Title, FileName (имя по умолчанию), метод ShowDialog() и также 
свойство FileName для получения выбранного пути.

– Почему работа с файлом помещена в блок try-catch и какие ситуации он покрывает?
Ответ: Работа с файлом помещена в блок try-catch, потому что операции ввода-вывода и десериализации могут завершиться ошибкой по целому ряду причин, не зависящих от программы: файл может быть занят другим процессом, у пользователя нет 
прав на запись, диск может быть переполнен или отключён, JSON может быть повреждён или не соответствовать ожидаемой структуре, а также возможны исключения IOException, UnauthorizedAccessException, JsonException и другие. 
Блок try-catch позволяет перехватить эти ситуации и показать пользователю понятное сообщение через MessageBox, вместо того чтобы приложение аварийно завершалось с необработанным исключением

– Почему после загрузки файл нельзя просто присвоить свойству ItemsSource, а нужно заполнять существующую коллекцию?
Ответ: После загрузки файл нельзя просто присвоить свойству ItemsSource, потому что ItemsSource — это свойство элемента управления, и присвоение ему новой коллекции заменит привязку, разорвав связь с той коллекцией, на которую уже 
подписаны команды, счётчик Summary и обработчик CollectionChanged в модели представления. Чтобы сохранить все эти связи и уведомления, нужно очистить существующую коллекцию Todos и добавить в неё элементы по одному — тогда сработает 
CollectionChanged, обновится сводка, и все привязки останутся рабочими.

– Какие данные объекта попадают в JSON, а какие нет?
Ответ: В JSON попадают только те данные объекта, которые являются публичными свойствами с геттером и сеттером, — в случае TaskItem это Title, IsDone, Priority и CreatedAt. Не попадают в JSON служебные члены класса: событие PropertyChanged, защищённый метод OnPropertyChanged, приватные поля _title, _isDone, _priority, _createdAt (сериализуются именно свойства, а не поля), а также любые члены, помеченные 
атрибутом [JsonIgnore].
